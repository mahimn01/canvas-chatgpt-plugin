# Hosted deployment candidate

The hosted mode is not yet validated against a live Canvas OAuth key and identity provider. Complete this integration work before accepting real public users.

1. Obtain institution-approved Canvas developer keys. Register the exact `https://YOUR_DOMAIN/canvas/callback` redirect and only the GET scopes in `src/canvas_companion/scopes.py`. Verify these against the institution's actual Canvas release.
2. Configure an established OIDC provider with an HTTPS issuer origin, RS256 access/ID tokens, rotating JWKS, authorization code + PKCE S256, refresh tokens for ChatGPT, and the `canvas:read` scope. Access tokens must contain `sub`, `iss`, `aud`, `iat`, `exp`, and a space-delimited `scope`; the exact audience/resource is `https://YOUR_DOMAIN/mcp`.
3. Register a confidential browser client with redirect `https://YOUR_DOMAIN/auth/callback`. Configure a separate ChatGPT OAuth client using its documented callback, or supported client registration. Both clients must resolve the same user to the same stable `sub`; providers using pairwise subjects need an explicit design before deployment. Require a verified email in UserInfo. The issuer must meet ChatGPT's OAuth discovery/client-registration requirements; this project does not implement its own authorization server.
4. Copy `.env.example` and `institutions.example.json` into private operator configuration. Supply secrets through a secret manager/environment. Set `MODE=production`; startup rejects missing credentials. Generate a Fernet key once and retain it securely across restarts. Losing it makes saved grants unreadable. Key rotation is an operator migration, not automatic.
5. Serve HTTPS through a trusted reverse proxy. Run exactly **one ASGI worker** per SQLite database. Set a private persistent database directory, request-size and per-user/IP rate limits, timeouts, a non-root isolated runtime, and an egress policy permitting configured public provider/Canvas hosts. Extraction must not have access to host credentials or network services. Linux subprocess memory limits complement container limits.
6. Disable access logging of query strings and Authorization headers. The callbacks contain one-use codes/state. Example: `uv run uvicorn canvas_companion.web:create_app --factory --host 127.0.0.1 --port 8000 --workers 1 --no-access-log`. Configure the reverse proxy likewise. Do not use reload mode for public service.
7. Test login, consent cancellation, incorrect state, cross-user requests, Canvas expiry/refresh, disconnect/revocation, expired ChatGPT tokens, JWKS rotation, and inaccessible/redirected files with real test accounts. Automated tests exercise boundaries but do not prove a deployed provider is compatible.
8. Publish final privacy/terms/support pages naming hosting and identity providers, retention, backups, incident contact, and deletion process. Current `/privacy` and `/terms` are development text. Set `OPENAI_DOMAIN_CHALLENGE` to the exact verified-domain challenge from the submission dashboard.

Browser linking stores only the identity subject, encrypted Canvas tokens, session state, and expiry times. Course responses are not persisted in the application database. Infrastructure logs/backups and the MCP client's records have separate retention that the deployment operator must document.

The existing SQLite/lock design is intentionally single process. Before horizontal scaling, replace it with transactional shared storage and cross-process refresh/revocation locking. Protect the public service against request floods; the per-process tool concurrency limit is not distributed rate limiting.

References: [OpenAI authentication](https://developers.openai.com/plugins/build/auth), [MCP server](https://developers.openai.com/plugins/build/mcp-server), [Canvas OAuth](https://developerdocs.instructure.com/services/canvas/oauth2/file.oauth).
